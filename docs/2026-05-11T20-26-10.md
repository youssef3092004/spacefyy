# Spacefyy API — Customer Discount Feature
Generated: 2026-05-11T20:26:10

---

## Overview

Customers can now have a **persistent discount** (`discountType` + `discountAmount`) that is automatically applied to every order they place. If the order also has its own discount, **both stack** — the order discount is applied first, then the customer discount is applied to the result.

### Stacking Example
```
totalPrice          = 200 EGP
order discount      = FLAT 20        → 200 - 20  = 180
customer discount   = PERCENT 10%    → 180 × 0.9 = 162
finalPrice          = 162 EGP
```

## Schema Changes

### Customer (new fields)
| Field | Type | Default | Notes |
|---|---|---|---|
| `discountType` | String | `"FLAT"` | `"FLAT"` or `"PERCENT"` |
| `discountAmount` | Decimal | `0` | EGP amount or percent value |

### Order (new fields)
| Field | Type | Default | Notes |
|---|---|---|---|
| `customerDiscountType` | String | `"FLAT"` | Snapshot of customer discount type at order time |
| `customerDiscountAmount` | Decimal | `0` | Snapshot of customer discount amount at order time |

## Updated Endpoints

### POST /api/v1/customers/create *(updated)*
Now accepts optional `discountType` and `discountAmount` at creation time:
```json
{
  "businessId": "...",
  "name": "Youssef Ahmed",
  "phone": "+201058716244",
  "discountType": "PERCENT",
  "discountAmount": 10
}
```
Both fields are optional — default is `"FLAT"` / `0`.

---

### PATCH /api/v1/customers/update/:customerId *(updated)*
Accepts `discountType` and `discountAmount` to set or change the discount after creation:
```json
{
  "discountType": "PERCENT",
  "discountAmount": 10
}
```
To remove the discount:
```json
{ "discountAmount": 0 }
```
Validation (applies to both create and update):
- `discountType` must be `"FLAT"` or `"PERCENT"`
- `discountAmount` must be ≥ 0
- If `discountType` is `"PERCENT"`, `discountAmount` cannot exceed 100

---

### POST /api/v1/orders/create
Response now includes the full discount breakdown:
```json
{
  "success": true,
  "data": {
    "totalPrice": 200,
    "discountType": "FLAT",
    "discountAmount": 20,
    "customerDiscountType": "PERCENT",
    "customerDiscountAmount": 10,
    "finalPrice": 162
  }
}
```

**How auto-discount works:**
1. If `customerId` is resolved (from visit or direct body), the customer's `discountType` and `discountAmount` are fetched automatically.
2. If the customer has a discount (`discountAmount > 0`), it is applied after the order-level discount.
3. The customer discount is snapshotted into `customerDiscountType` / `customerDiscountAmount` on the order for auditing.
4. If the customer has no discount (`discountAmount = 0`), no customer discount is applied.

---

### PUT /api/v1/orders/:orderId
When items are updated, `finalPrice` is recalculated using **both** the order-level and customer-level discounts stored on the order (no re-fetch of customer needed).

---

## Discount Rules Summary

| Scenario | finalPrice formula |
|---|---|
| No discounts | `totalPrice` |
| Order discount only | `applyDiscount(totalPrice, orderType, orderAmount)` |
| Customer discount only | `applyDiscount(totalPrice, customerType, customerAmount)` |
| Both discounts | `applyDiscount(applyDiscount(totalPrice, orderType, orderAmount), customerType, customerAmount)` |

`finalPrice` is always clamped to `≥ 0`.
