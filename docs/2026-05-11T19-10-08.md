|---|---|---|---|

## New Endpoints

### Block a Customer
```
PATCH /api/v1/customers/block/:customerId
Auth: Bearer token  |  Permission: UPDATE_CUSTOMER
Body: { "reason": "string (optional)" }
```
Response `200`: updated customer object.
Error `400` if already blocked. Error `404` if not found.

---

### Unblock a Customer
```
PATCH /api/v1/customers/unblock/:customerId
Auth: Bearer token  |  Permission: UPDATE_CUSTOMER
Body: (none)
```
Response `200`: updated customer object.
Error `400` if not blocked. Error `404` if not found.

---

### Create Takeaway Order (Order Without Visit)
```
POST /api/v1/orders/create
Auth: Bearer token  |  Permission: createOrder
Body:
{
  "branchId": "string (required when no visitId)",
  "customerId": "string (optional)",
  "items": [{ "productId": "string", "quantity": number }],
  "discountType": "FLAT" | "PERCENT",   // optional, default "FLAT"
  "discountAmount": number               // optional, default 0
}
```
Response `201`: created order with `totalPrice`, `discountAmount`, `discountType`, `finalPrice`.

## Blocking Behaviour

When a customer has `isBlocked = true`, the following endpoints return `403`:

| Endpoint | Trigger |
|---|---|
| `POST /api/v1/visits/start` | checked via `customerId` in body |
| `POST /api/v1/sessions` (createSession) | checked via visit's `customerId` |
| `POST /api/v1/orders/create` | checked via visit's `customerId` or direct `customerId` |

Error response:
```json
{ "success": false, "error": "Customer is blocked: <reason>" }
```
